# Social-AnimaI-Icons

**▶️ [Live demo](https://mecca-research.github.io/Social-AnimaI-Icons/)** — runs entirely in your browser, no install required.

![Social Animal Icons — 14 distinct hand‑drawn forest animals (fox, wolf, bear, cougar, deer, beaver, canada goose, skunk, grey squirrel, turtle, hedgehog, raccoon, frog, owl) roaming a lush, textured top‑down forest lit by volumetric god‑rays, around a big organic lake where a turtle swims inside a ripple ring.](media/screenshot.png)

An interactive, emergent “living desktop” made of animal icons that socialize, argue, help each other, and roam **switchable worlds** — a forest around a lake, or a suburban neighborhood of rooftops. Every icon runs a tiny state machine (wander, idle, swim, friendly, fight, rescue, flee, separate, cooldown, drag) and forms relationships via last-touch memory (friend or rival).

Current release: v0.42 — **One log, one animal, and a bluff you have to climb down.**

**The dam is empty when you open it, and the beaver carries one log.** It was five logs a trip, then fifteen, both times to make it finish sooner — and both times that solved the wrong problem, because seven trips to raise a hundred logs is a delivery rather than a beaver. A hundred crossings is a long watch and that is the point: the finished dam is what leaving the simulation running buys. The squirrel's drey goes back to being hauled up course by course for the same reason. **Dropping an animal over the side counts as gone** now — the wrap only spoke once something was 70px past the boundary, which is right for one who wandered out and wrong for a deliberate throw, so a drop that landed 60px out was worth nothing and the beaver simply walked back in. A drop six pixels past the edge puts him in the errand on the very next frame, and one throw is worth one log.

**Only three animals come off the cave-entrance ledge.** The cougar jumps, landing clear of the face because the arc reads the break line at the x he ARRIVES at; the owl and the goose fly down, which is a different motion and not a leap — 1150ms against 520, run as two curves whose gap IS the altitude, so the wings stay out the whole way. Everyone else is refused and steers to the nearer of the mid-riser step or west off the stage. Soaked at six trials a species from three points on the shelf: **84 of 84 reached the ground, nothing stranded**. It costs foraging time and the honest number is in the notes — a skunk goes from about nothing on the bluff to 6-13% of its day. Going UP is untouched, byte-identical per species at both faces.

**An ascent holds its x**, which the code's own comment claimed and the code did not do: with no held x a cliff hop drifted about 47px east mid-arc, far enough to land past the bluff's drawn outline where the level is forgotten — which is how a fox arrived at plateau latitude standing on forest floor, having climbed nothing.

**The fruit tree by the rock stops painting over it.** It was level with its neighbour and its crown covered 24% of the shelf and 31% of the standable step. It moves down and east and comes down from 1.38 to 1.05, and the trim was forced rather than chosen: the binding dimension is the crown's TOP, not its west edge, because the bluff holds 114-116 per-mille of width from the shelf lip down and a crown clears it by dropping BELOW that band. At full size that needs an anchor off the bottom of the stage. Every band goes to zero, all six trees now clear the rock, and the tightest west working face on the map — this same tree — goes from 8.3px of forest floor to 44.0px.

**The speed slider is gone and a world opens with one animal**, added to by hand up to the roster's ceiling.

That last change quietly broke the test suites twice, which is the part worth recording. Every suite looks its subjects up by species, so with one animal they found nothing and checked nothing — the world suite produced no output at all rather than failing. And the forage suite reached into the DOM for the slider to wind the world up past its wall-clock give-up timers, so removing the widget CRASHED it at exit code 0, taking every check after that point. Both go through the world's own hooks now.

One check in this release failed four times running for four different reasons, none of them the beaver: a muzzle inherited from checks that park the cast, a dam another check had finished and never put back, an errand picked up in the frames before the drop, and a budget written in wall-clock against clamped simulated time. It runs first now, against a world nobody has touched. The general lesson, four releases deep: **a check that reports what it was looking at costs one cycle; a check that only says "failed" costs four.**

Built on v0.41 — **A staircase up the bluff, trees that fit their window, and the build that was never shipped.**

**The two bugs reported against v0.40 were one bug, and it was in the shipping, not the code.** `npm run build` is two steps — `vite build` writes `dist/`, and `scripts/publish.mjs` then copies it to the repo root and `docs/`, which is what GitHub Pages serves. v0.40 was built with `vite build` alone, so every fix landed in `dist/` and **the served bundle never moved**. What shipped was an intermediate state carrying the old fourteen-log dam and a `tryRockHop` with no on-rock gate — so hops fired anywhere along the break lines, which run as arithmetic right across the map, and an animal on flat grass in the middle of the lake's latitude would jump. Measured against the published bundle: 30 off-rock hop starts reaching 98% of the stage width. Against the source: none beyond 9%. There is a publish check now (`scratchpad/verifypub.sh` in the working notes, and the same probes) that serves the repo root and asks the SERVED files for the dam plan's length and whether a hop can start off the rock — the two things that were wrong — because a suite that only ever ran against the dev server could not have caught this and did not.

**A false alarm worth recording.** Painting the rock's interaction region over the art showed a boundary 30–60px east of where the bluff reads, and it was reported as a defect. It is not one: `rockZone` and the drawn outline are the same points, 0px apart at all 41 sampled latitudes. The gap is the west-low oak's crown painting at z-index 12 over the shelf's east nose. Hiding the foliage puts the boundary back on the rock exactly.

**The climb to the cave entrance is a staircase.** It was one arc up a bare face; there is now a ledge cut into the riser with a rock on it, and the long slab on the shelf above — talus, step, shelf, slab, three arcs with each apex above both of its ends, and the new ledge halves the climb at 58px then 49px against 107px in one go. **Where an animal stands on a platform had to be measured rather than judged**: `a.y` is the sprite box's CENTRE, not the feet, so the paws land about 0.97r below the anchor. On a 90px terrace that is invisible; on a 22px slab it is the whole difference between standing on the rock and standing in front of it. Drawn paws land on the drawn lip to 0.00px at four window shapes, and the suite asks the PAINTED polygon whether the standing line is inside it rather than carrying a copy of the geometry. Found on the way: `tryRockHop`'s landing pad had its sign inverted, so every face hop on this bluff had been finishing a pad's depth inside the wall it had just cleared and being snapped back out — a 16–33px twitch at the end of every hop since elevation shipped.

**Crowns are sized against the stage.** A crown was drawn `topPx*s` pixels tall over an anchor held as a stage FRACTION, so how much of it fitted was `y*h` against `topPx*s` — a race the tree lost as the window shortened. The code had written off both consequences: the west-high pine's note claimed 1.10 kept its leader on screen (it was cut at four of eight shapes, by 81px at the shortest), and a note on the east pair called closing crown gaps "structural, and no placement fixes it". Neither was structural; both were this. Scale is now `s0 * treeScale(bounds)` with the authored value kept aside, and the basis — the geometric mean the dam already uses, **capped at the height ratio** — makes the ceiling shape-independent: `tip = h * (y - topPx*s0/872)`, the `h` divides out of the sign, and a crown is whole at every shape or at none. Worst case across eight shapes: crown tip −81px → +12px, crown-to-crown gap −21px → +34px. Four shapes had a beheaded tree and four had two crowns painted as one; none does now, and the reference stage is byte-identical by construction.

**Both evergreens are the same tree.** The west-high pine goes 1.10 → 1.56, asked for three releases ago and refused twice on the evidence. It is possible now because the ceiling is one latitude threshold: 1.56 needs `.4150` of stage above its anchor and that corner had `.315`, so the resize is a MOVE as well as a scale and the tree comes down 148px. **One object was the whole obstruction** — with the browse shrub at (.225,.455) in place a 1.56 pine has zero legal anchors anywhere in the west; moved 102px it has 840, and the tree sits at the max-min centre of them rather than the first cell that fits. The world's tightest crown clearance IMPROVED from 14.3px to 44.8px in the process, and it was this same tree that held it.

**The dam builds in half the time.** A trip carries fifteen logs, not five. Measured: a trip costs about 80 seconds of which only 18 is the crossing and the laying — the other 62 is the beaver wandering until he happens to cross an edge, since `offstage` is the only way into a run. The cost of the dam is therefore very nearly the cost of its trips, so the lever is the load. A hundred logs closes in 13.7 minutes across seven trips against 27 before, verified end to end with the plan actually reaching 100.

One thing got worse, and it is the price of the crown fix: on stages under about 700px tall the bear's climb depth clamps, because the tree now shrinks and the bear does not, so his head no longer disappears into the boughs there. A beheaded tree is on screen always and a shallow climb is a few seconds a minute, so the tree wins. A new check — every trunk works its west face on forest floor, a rule the bluff created that nothing was testing — also found the west-low oak with only 8.3px of forest floor at 1008x700, tighter than the tree this release moved and boxed in on both sides: 1.3px outside a surface root's ring, and 1.3px off the map's tightest crown pair.

Built on v0.40 — **The bluff gets height, and the beaver gets a dam.**

**The rock formation has elevation.** It was scenery with a cave painted on it; it is terrain now, in three terraces with a wall between each. The lowest walkable ground begins exactly where the brief drew its line — the talus at 626 per-mille against a line drawn at 629 — and everything above it has to be earned. Nobody walks in from off screen through a face or onto a terrace they would have had to leap to reach; the owl and the cougar are the two allowed in high. Walking cannot change level, so each face is crossed on an arc, and **the three ways up the brief named each have a referent**: a fox and a deer jump the 140px cliff, the cougar and the squirrel climb it, the owl flies it, and the bear, wolf, raccoon, skunk, hedgehog, beaver and goose get the shelf and the cave and no further. The turtle and the frog take none of it — the frog out-jumps every one of them on the flat and still cannot climb rock, which is the difference between a leap and a scramble. Coming down, land animals lower themselves one terrace at a time; the owl skips the shelf entirely and takes the whole bluff in a single glide.

**The cave is a room, not a hole in a wall.** Its ceiling lifts across the mouth to the back wall and its jambs are solid, and which way an animal gets pushed is decided by **which face is nearer** — step off the east jamb by a pixel and you are put back a pixel, rather than dropped the height of the room onto the shelf. The east outline of the whole mass turned out to need the same treatment for the same reason: an animal on a terrace who walks off the side of it would arrive at ground level having descended nothing, and coming the other way a one-pixel step into the side of the bluff was dropping an owl 143px onto the talus.

**The dam is a hundred logs and it is ground you can stand on.** Fourteen logs in three arcs read as a pile; this is four courses of arch laid serpentine along the lake's west end, straddling the water-and-mud seam and bedded into each other so no water shows between them, with a dome of straight parallel courses inside it turned ninety degrees level by level. It takes 19.3% of the lake and leaves nothing walled off behind it. Every count is figured at a reference stage size, so `damCount` means the same thing on any window.

**A placed log is land**, and that is one line inside `inWater()` — the question every other caller in the world already routes through, so nine call sites were corrected by one edit. Behind it is a two-pixel raster of the drawn barrels built once per window size, which makes the test a byte compare rather than a hundred rotated rectangles, and correct at **every stage of the build** rather than only when the dam is finished. `keepAshore` knows a log is somewhere to stand now: step off one into open water and you are put back on the log, not shoved a quarter of the lake west by a radial push. Five species that had never legally been inside the lake's outline — fox, hedgehog, squirrel, skunk, owl — can walk out onto the beaver's work, and over ten minutes of soak not one of them got wet.

**The raccoon wades to the lip.** He was taking the deeper three quarters of his standing band, which put him up to twenty pixels out from the bank for no reason a viewer could see, when the whole point of the band is that its shallow end is already the last place he can stand and still be drawn on water. He takes the shallow tenth now — the water tile against the ground tile, touching it, over none of it, with his lowest ink one to two pixels inside the drawn waterline at due south. And his walk there routes **around** the dam: of 248 straight lines from a forage site to a wash spot, 91 crossed timber and 2 do now.

Two checks that measure a *rate* were rewritten, because both had been reporting on the draw rather than on the build. The bear's fish-on-entry read 15% on a build that measures 29% over 400 entries — at 80 samples a window tight enough to catch a real halving sits 2.6 sigma out and fails one run in a hundred — so it now buys a second sample when the first lands borderline and judges the two pooled. The skunk's dig budget said "no pit was dug inside 120s" on a build that dug three in well under that on the runs either side; it is a ceiling the loop leaves early, so raising it costs nothing when the world is healthy.

Built on v0.39 — **A bluff on the west edge, and a hedgehog who finally uses the world's wood.**

**The hedgehog stops bringing his own root.** The log was only half of it: both ROOT poses still painted a whole surface root apiece — `rootdig` a pair of tapered slabs with the dark underneath, `rootbore` a three-ellipse mass plus the cavity his head sits in and a lower lip in two pieces. Same cause as the log in v0.37: the sprite paints at z-index 10 and the forage sites at 2, so the root he walked to could never cover his snout, and a second root had to exist inside the animal for the pose to read. The world root's own art said so out loud — *"the arch the hedgehog actually works is painted by his own pose on top of this"* — and two competing arches is precisely what was being seen. `ForageCanopyLayer` draws the root's **near half** again at 12 now, the same centre line dropped six units and half as thick, and both variants aim at the two dark openings the site already paints.

**A rock formation down the west edge**, and only the bottom of one: the mass runs off the left of the stage and off the top, and what is on screen is its last two steps — an upper plateau, a tall faceted cliff with a **cave** cut into it, a broad lit shelf standing out in front with fallen blocks on it, then a riser and a talus of broken rock spilling out of the bottom of the frame. It is a stage layer and not background art, for the third time in this project: `xMidYMid slice` pins the CENTRE, so a background y drifts up to 9% of the stage height across the shapes this world is checked at, and the formation's foot has less room than that against the west-low oak. The integration came free anyway — the layer paints ForestScene's **own** vignette and grain, clipped to its silhouette, resolved across the document the way `PlantLayer` resolves the fern gradients.

**The ferns and reeds are on the lake and nowhere else**, swept round the shore rather than placed: each is the first radius out from the waterline, at its own angle, that clears every trunk, every site, the sward and the edges at nine stage shapes — past the mud liner, which runs rho 1.00 to 1.08, so nothing stands on the wet. Top and bottom arcs sampled twice as densely as the flanks. The west shore returns nothing at all, correctly: the clearing's own sites own that ground.

**And the surface root that looked like a log** has left the spruce. At (.170,.150) it was drawn straight through the west-high conifer's crown — the one arch on the map you could not tell from a fallen trunk, in the one place a trunk had no business being.

One bug the work surfaced: the skunk's pit clearance was checking the ground he **stands** on rather than the ground the hole **lands** on, and `dropPit` puts the hole 24px in front of him with another 26px of arrival slack behind that. A pit inside a bush is one the bush paints over — the exact fault the rule was written to stop.

Built on v0.38 — **A cleaner floor, a forest with depth, and animals that get on with it.**

**The clutter is gone.** The four-leaf clovers, the six-petal flowers and the scattered brown pebbles were decoration with no behaviour behind them, and fourteen animals on one map is already a lot of silhouette. The ferns and reeds stayed, but they moved out of the background: they were generated inside a `xMidYMid slice` viewBox, which crops the short axis, so every one of them **slid across the map as the window changed shape** — a fern clear of a trunk at one aspect grew out of it at the next, and no amount of nudging them inside that viewBox could fix it, because the thing they were in the way of is anchored differently. They are stage fractions now, like the logs, and solved rather than placed.

**The forest has depth that works.** v0.37 shipped a rule for this and the big trunks still had animals walking up them. The exception was `TREE_REACH` — the radius at which the *bear takes an interest*, an unscaled 96px that reaches straight up the bark and swallowed 68–75px of every trunk on the map. It is the tree's own working line now, read off the same two constants the behaviours use, so it scales with both the tree and the animal. Logs had no depth rule at all: 84% of a mossy log and 96% of a rotten one had nothing above the animals. The exception there cannot be geometry — "on the log" and "behind the log" are the same band — so the site claim decides it.

**Two evergreens, and the owl has two nests.** The west-high oak is a conifer, and the nest became a rule over a set rather than an index: every lake-clear evergreen carries one, and the owl takes the nearer and commits to it for the trip. The two east-flank trees were solved as a pair a second time — their crowns *overlapped by 35px* and read as one lumpy mass — and now stand 174px apart with daylight between them.

**Four behaviours came back.** The raccoon douses **in** the water on the south shore: `rho 0.93` was a number about his anchor while the wash pose hangs 24.7px below it, so every mark that makes the douse read was landing on the mud liner. The cougar has stopped panting — he did it on 87% of frames, because the exertion ledger rests at a level set by a species' top speed and one flat threshold read the three fastest animals as permanently blown.

And the fox, the goose and the hedgehog all feed again, for one reason. v0.36 dialled forage balance on **share of the clock**, and a duty cycle is blind to how often a bout *starts* — which is the only part of it a viewer can see. The whole correction came out of the appetite windows, and nothing noticed: the fox foraged once every 7.1 minutes, the goose once every 3.4 with a 27-minute gap between grazes, and the hedgehog **balled up more often than he ate**. Half the goose's dabbles were happening behind a tree crown, too — "no crown over the goose's sward" had been a rule since v0.36 and was never asked of the water half of his feeding. There is a floor under bout frequency in the suite now, so a future retune cannot do this quietly again.

Built on v0.37 — **What you see is what the table says.**

**Every sprite is resized on its drawing, not on its box.** `size` set the sprite box and nothing else — and each species' art is scaled again inside that box, filling anywhere from 0.47 of it to 1.02. So the table read bear-first while the SCREEN read wolf, deer, cougar, fox, BEAR, with the heaviest animal on the map in fifth place and the hedgehog as wide as the fox at a fourteenth of his body length. `size` is derived now: real mass, body length and shoulder height give a bulk index, that gives a target on-screen size anchored on the bear at 70px, and the radius falls out of the target divided by how much of its box that drawing actually covers. The frog lands at 36% of the bear against a real 10% — legible, and still a hierarchy. The order is not tuned; it falls out of the index, bear first, frog last, hedgehog eleventh.

Getting a number that meant the same thing twice took three attempts, and the fault was never in the table. `getBBox` reports a leaf in its own user space and ignores the art wrapper above it. The sprites breathe — the bear as a scale on his whole `<svg>` — and the cougar's idle cycle is longer than any sample window, so the same build gave 59.6px of cougar in one run and 52.9px in the next. And `state='idle'` set once does not stay idle: fights are struck world-side off proximity, clearing the ethogram state in fact *invites* a fresh behaviour because the engine rebuilds with every cooldown at zero, and `data-state` is only one of eight attributes the renderer poses off — an animal in the lake got measured mid-paddle. Pinned, the reading is byte-identical run to run and every row of the table moved under 1%. Held in [`tests/sizes.mjs`](tests/sizes.mjs) (`npm run test:sizes`).

**Animals go behind trees now, and three animations stop faking it.** World art painted *under* animals — sites at z-index 2 against sprites at 10 — so anything meant to hide part of an animal had to be drawn inside that animal. The forest is depth-sorted instead: an animal whose feet are above a trunk's base and whose body crosses the bark passes behind it, while one standing at the tree is touching it, not buried in it. On the back of that, the hedgehog **stops bringing his own log**. He used to paint an entire section of timber — bark, moss, end rings, rot hole and rim — because a log has to be *under* the animal standing on it and *over* his head at the same instant. Now the two scenery logs are promoted to real, fraction-anchored sites (they lived in a `slice` viewBox and slid across the map as the window changed shape), making four logs of two kinds, and he works each the way it lets him: head-first down the hole in a **rotten** one, nosing under the near edge of a **sound mossy** one. And the goose's dive is a real cut at the waterline rather than a translucent tint over the parts meant to be submerged — head and neck simply stop existing below the meniscus.

**Five trees moved, and every position was solved rather than judged** — against no forage site within 96px of a trunk, no west-facing working spot in the lake, no crown over the goose's sward, and no trunk nearer another than the world's own tightest pair, checked at a dozen window shapes. Two of them had to be solved as a *pair*, each being the other's blocker. Three reeds standing where a tree now grows are held out by a keep-out box rather than deleted, because the scatter is seeded and changing the count reshuffles every tuft after it.

Built on v0.36 — **Balanced by time, not by count.**

Forage balance is dialled on the **share of the clock** each animal spends feeding, rather than on how often a bout starts — and the change was a correction, not a refinement. On the old metric the ladder read skunk 1.41 bouts/min, deer 1.15, bear 0.70 and looked right. Measured as time spent, the same build had the **bear on top at 39.8%** and the goose above the skunk: a bear's berry strip is one 34-second bout against the skunk's 11 seconds nosing windfall, and counting starts weights those equally. Now skunk 28.8% · deer 21.5% · bear 15.8% · squirrel 11.8% · raccoon 5.9% · fox 1.8%, with nothing over a third of its day.

Bout lengths are **derived, not measured**, and that is deliberate: a bout is part fixed-duration states and part walking, headless frames run ~3fps against a real 60, and a stopwatch would have returned a number dominated by that artifact — eating the walk half, which is exactly the half separating the bear from the fox. The arithmetic lives in [`tests/cadence.mjs`](tests/cadence.mjs) (`npm run test:cadence`).

An adversarial audit of the two previous releases also fixed four defects, three of which every suite was structurally blind to because they only appear on an **interrupted** bout: the bear's sweep tested one specific facing value and so left him walking backwards forever after any interrupted berry strip; the same sweep never returned his site claim, quietly removing a bush from the shared pool; the east-flank tree had its west-face working spots **inside the lake**, so a bear rearing against its bark played the swimming rig; and dragging one animal out of a fight was dead code, leaving the other stuck at its locked contact point. All four are pinned in [`tests/world.mjs`](tests/world.mjs) (`npm run test:world`).

**The two lenses that had not run then have now**, and found six more — four defects and two numbers describing them. Two trunk pickers could not see each other: a tree is not a claimable site, so the only record that one is busy is the animal standing at it, and the ring they read it at was smaller than the distance a bear actually stands from a trunk. The goose's lawn had been laid **under the lone spruce** while fixing the mud problem — a crown paints over the animals on purpose, so 56% of the sward had the bird invisible for his longest bout, and the lawn has moved east to the lake's south shore, measured clear at fourteen window shapes. Eleven drifting floats were dealt three bob phases off a nine-character string, so two big drift logs rocked in exact lockstep. And the skunk's pits kept a flat clearance that is a *bush's* number, so a hole could land under a fallen log drawn nearly a third wider and be painted over by it. The two numbers were the raccoon's bout length — his tree variant carries fruit to the water from a **trunk**, not a bush, which is 404px rather than 209 — and the goose's walk, which moved with his lawn.

Built on v0.35 — **Five more species get an inner life.** The **raccoon** roosts out the daylight in a hollow log or tree cavity, climbs fruit trees, and his dousing was corrected: it is not washing food, it is wetting and rubbing the paw pads to sharpen touch. The **fox** screams and barks for a mate, plucks low berries, takes windfall and chews soft grass — all as variants of his existing appetite, which is what keeps him bottom of the ladder. The **owl** gets its first ethogram: deep hooting, and a nest it flies up to and freezes against the trunk in. The **squirrel** trades one larder for **four fixed, invisible, anchored cache spots** — dig, place one nut, pat the dirt back, and return to the exact same spot for it — plus a drey woven high in a tree fork and zig-zag escape sprints. And three species get their own **fight displays**: the skunk's aposematic stamp-and-arch followed by a green musk cloud that forces an extra flee, the goose's neck-low hissing charge, and the squirrel's tail-flick chatter.

Built on v0.34 — **Terrain, and break-ups that move.** The goose was dabbling on the mud liner, and the band was measured against the wrong thing: the rim is *outside* the waterline, and what put him on it was his own drawing, whose water lens reaches 32px below the anchor. The usable band is now computed per angle from the pose's measured reach. His sward was 68% mud with its own centre on bare earth, so it moved to the grass verge between the earth patches and the shore. Break-ups no longer walk apart in a straight line and stand frozen: each animal independently rolls a short dash or a longer walk-off, on its own heading, with the standing pause gone and the cooldown untouched. The west berry thicket moved to a **second foraging ground** in the south-east with two nut trees; the trees grew 10% in the trunk and 20% overall; and two more joined them, including a **lone spruce** standing by itself at +30%.

Built on v0.33 — **Every animal moves like itself.**

**Size is the species now, not a dice roll.** Every animal drew its radius from `rand(18,24)*1.1` at spawn, so the same bear was a different size every reload and sometimes came up smaller than the squirrel standing next to him. Sizes are now derived once from real-world mass, body length and shoulder height — `M^(1/6) · L^(1/4) · H^(1/4)`, tail excluded — anchored with the bear as the largest at +20% and the frog as the floor, and held in [`app/src/SpeciesProfile.js`](app/src/SpeciesProfile.js) alongside each animal's real dimensions, top speed and habits.

**And speed is the species too.** [`app/src/Gait.js`](app/src/Gait.js) gives each animal a cruise, a top, a stamina drain, a burst rate and a water factor, and every call site states an *urgency* — 0.30 for an amble, 0.45 for an errand, 1.0 only for the dash to break up a friend's fight — which the animal prices for itself. The turtle used to cross the entire screen at a wolf's pace because its swim leg was a flat multiple of one global speed; that flat multiplier is gone from all of them. Measured in-world while wandering: **wolf 80 px/s down to turtle 24**, with the frog sitting at 6 and peaking at 93, because a frog travels by leaping rather than walking. Speed also varies continuously — a two-harmonic drift so it never reads as a loop — and a sustained sprint tires: a cougar flat out for ten seconds drops from 154 px/s to 61. Checks live in [`tests/gait.mjs`](tests/gait.mjs) (`npm run test:gait`).

Social logic

Encounters happen only at true nose‑range (~70–85 px), anywhere on the map: ~40%/sec attempt per close pair, 50/50 friendly vs fight.

Interaction lock: friendly or fight pulls the pair together nose‑to‑nose, facing each other, for 8 seconds of contact — synchronized nuzzling, lean‑ins and tail wags when friendly; alternating lunges, paw swipes and rearing when fighting (splashes for both when it happens in the lake).

Avoid confrontation: bystanders near an active fight steer away from it until it ends.

Break it up: a third animal whose last touch with one fighter was friendly sprints to the fight and breaks it up — the opponent flees, everyone involved cools down.

Separation & cooldown: after locking, icons visibly peel apart (~1.4 s), then wander and cannot re-trigger events for ~4.2–7 s.

Last-touch relationships: each pair keeps only the last interaction tag (friend|rival); the top bar counts friends/enemies from that.

Controls: Pause/Run, Speed slider (decently slow → brisk), Add/Remove Icon (start 8 unique species, cap 14 — one of each), Reset World. The selected animal (double‑click one) shows mid‑top‑bar with its Friends/Enemies tally.

## 🐻 Species behavior: the ethogram

An *ethogram* is a biologist's catalogue of what an animal does. [`app/src/Ethogram.js`](app/src/Ethogram.js) makes that catalogue executable: a species declares its domains and its events as data, and one scheduler turns it into activity. The world's own mechanics are untouched — encounters, wander, navigation, physics and the intent roll all run exactly as they did. An ethogram only decides which **species-specific** action starts, and when.

| tier | what it decides | how |
| --- | --- | --- |
| 1 · domain plan | *where* he means to be | shares of time between `land` and `water`, weighted by a decaying ledger of where he has actually been, so the split converges instead of drifting. The dwell clock starts on **arrival** — the lake is a walk away |
| 2 · trigger | *whether* something may start | `enter` · `exit` · `dwell` · `approach`, edge-gated to fire once per crossing |
| 3 · event | *what* happens | chance → cooldown → optional armed delay → `begin`, then the event's `drive` owns the frame until it calls `endEvent`. Weighted `variants` split one roll into flavors |

**Adding a behavior** is one descriptor appended to a species' `events`. The states it owns register themselves as busy — so the intent roll and the encounter engine leave them alone — and its cooldowns and edge gates are handled for you:

```js
{ id: "bark", domain: "land", trigger: "approach", chance: .25,
  cool: 20000, states: ["barkstrip"],
  near: (a, c) => nearestTree(a, c),
  begin(a, c, S, tree) { a.state = "barkstrip"; a.stateUntil = c.now + 4000; },
  drive(a, c) { a.vx = a.vy = 0;
    if (c.now >= a.stateUntil) endEvent(a, c, { reroll: true, quiet: 900 }); } }
```

**Adding a species** is one `defineEthogram("wolf", { domains, events })` call. A species with no ethogram is untouched — every entry point no-ops for it, the same code path as before.

Triggers are `enter` · `exit` · `dwell` · `approach` · `seek` · `offstage`. An event may also declare a `goto` — a walk-there leg the engine drives for it: pick a destination, claim it so nobody else takes it, walk, and hand over on arrival.

Every forest species now runs on this: bear, raccoon, squirrel, deer, skunk, fox, goose, frog, turtle and beaver. The neighborhood pets deliberately do not yet — see the note in `Ethogram.js`. Run the checks with `npm run test:bear` (the engine's three tiers) and `npm run test:forage` (the ground and everyone who works it) against a running dev server.

## 🌐 Live Demo & Deployment

**Live:** https://mecca-research.github.io/Social-AnimaI-Icons/

The site is a [Vite](https://vitejs.dev) build (React + Tailwind) published with **GitHub Pages → Deploy from a branch** — no Actions workflow and no build step on GitHub's side. The Vite source lives in [`app/`](app/); `npm run build` compiles it and publishes the result to **both the repo root and [`docs/`](docs/)**, each with a `.nojekyll` file. Because the build uses a relative asset base, the live site renders whether Pages serves the **`/ (root)`** folder or the **`/docs`** folder.

### One-time setup (repo owner)

**Settings → Pages → Build and deployment → Source: _Deploy from a branch_ → Branch: `main`.** Either folder — `/ (root)` or `/docs` — works, so no need to fuss over the folder dropdown. The site goes live at the URL above within a minute or two.

> The Vite `base` is `./` (relative), so hashed-asset URLs resolve from any served path, and the `.nojekyll` files tell Pages to serve the built files as-is (no Jekyll processing).

### Develop & publish

```bash
npm install
npm run dev      # start the Vite dev server (prints a localhost URL)
npm run build    # compile app/ and publish the build to the root + docs/
npm run preview  # preview the production build locally
```

Because Pages serves the committed build, **after changing the app run `npm run build` and commit the updated files** (the root build and `docs/`) for the live site to change. `app/src/` holds the simulation as a drop-in React component (`SocialAnimalIcons.jsx`, which exports `SocialAnimalsRPG`) plus the `App.jsx` and `main.jsx` entry files that mount it.
